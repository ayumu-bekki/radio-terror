# マネージャー運用マニュアル

RADIO TERROR を運営する人(マネージャー)のための手順書。
**当日はこの文書だけを見れば運営できる**ことを目指している。

- 作成日: 2026-08-09
- 対象: 会場でCoreを設置し、プレイヤーを案内し、無線で開始申告を行う担当者
- 設計の背景を知りたい場合は `operation_flow.md`(体験運用フロー)を参照

---

## 0. 用語

| 用語 | 意味 |
|---|---|
| プレイヤー | 遊ぶ人 |
| ナビゲーター | プレイヤーが無線で話す相手(生成AI)。4人のキャラクターから自動で割り当てられる |
| マネージャー | **あなた**。運営者 |
| Core | 危険物体験装置(風船入りの箱)。4桁のCoreIDで識別する |
| カラス | ゲーム開始前の無線に応答する疎通確認用の相手。ゲームの内容は知らない(§1.2) |

## 1. 起動前の準備(開場前に1回)

### 1.0 ホストの初期設定(最初の1回だけ)

`docker compose up` 時に Valkey が `Memory overcommit must be enabled!` という警告を出すことがある。
低メモリ環境(Raspberry Pi など)ではバックグラウンド保存が失敗する要因になるため、
サーバーを動かすホストで一度だけ設定しておく。

```bash
echo 'vm.overcommit_memory = 1' | sudo tee -a /etc/sysctl.conf
sudo sysctl vm.overcommit_memory=1
```

設定は再起動後も保持されるため、**新しいホストにセットアップしたときの1回だけ**でよい。

### 1.1 起動順序

1. **サーバー** を起動する
   ```bash
   cd app
   docker compose up -d
   ```
2. **Management Console** を開く: <http://localhost:8080/manager>
3. **Core** の電源を入れる
4. **トランシーバー**の電源を入れ、チームごとの周波数に合わせる

### 1.2 無線の疎通確認(カラス)

**ゲーム開始前に無線に話しかけると「カラス」が返事をします。**
これで無線・PTT・音声の経路がつながっているか確かめられます。

> あなた「こちらマネージャー。感度はどうか。どうぞ」
>
> カラス「こちらカラス。感度良好だ。どうぞ」

- **返事が返ってくれば経路は正常**です(内容は毎回変わります)。
- **雑談にも応じます。** 天気や機材の話などを振ると会話が続くので、
  音声の聞き取りやすさを確かめたいときはしばらく話しかけてみてください。
- **今日の天気・店の営業時間・観光地なども答えます**(その場で調べます)。
  話題に困ったらこの手の質問が使えます。
- カラスはゲームの内容を知りません。装置のことを尋ねても
  「何の話だ」と返ってくるだけで、ヒントは出ません。
- ゲームを開始すると、以降はナビゲーター(フクロウ等)が応答します。
- **返事がない場合**は §7.2 のトラブル対応へ。

### 1.3 起動確認(Management Console で見る)

画面の各節が次の状態になっていればOK。

| 節 | 正常な状態 |
|---|---|
| デバイス | Coreが台数分並び、状態が `setup` または `ready`。**「切断」と薄く出ていたら繋がっていない** |
| 無線 (bridge) | 使う無線の数だけIDが並んでいる |
| 外部API / アセット | 最終エラーが「—」(エラーが出ていない) |

**1つでも欠けていたら §7 のトラブル対応へ。**

## 2. 1プレイごとの準備

### 2.1 Coreのセッティング

1. **風船を膨らませて Core にセットする**
   - 膨らませすぎない。破裂時の音と飛散を考えて適度に。
2. **切断された配線を復旧する**
   - Core は準備中(**フルカラーLEDが黄色に点滅**)になっている。
     紫のままなら**まだサーバーに繋がっていない**ので、線を直す前に §7.1 へ。
   - **つなぎ直した線の色のLEDが点灯**します。**光っていない色が残りの作業**です。
   - 全部つなぎ直すと**5色すべて点灯**し、数秒後に**フルカラーLEDが青の点灯**に
     変わります(接触が安定しているか3秒確認します)。

### 2.2 状態の見分け方(Core本体のフルカラーLED)

| 色・光り方 | 状態 | 意味 |
|---|---|---|
| **紫の点灯** | 起動中 | サーバーに繋がるのを待っている。**線を直しても変わらない** |
| **紫の点滅** | Wi-Fi失敗 | Wi-Fiに繋がらなかった。§7.1 へ |
| **黄の点滅** | 準備中 | 線が切れている。**復旧すれば青になる** |
| **青の点灯** | 準備完了 | 開始できる |
| 赤の短い点滅 | プレイ中 | 残り**1分・30秒・10秒**で段階的に点滅が速くなる |
| 赤の点灯+ブザー | 失敗確定 | 2秒後に風船が割れる |
| 緑の点灯 | 解除成功 | 残り時間がスコアとして表示され続ける |

> **紫と黄で原因が分かれます。** 紫のままなら**サーバー側**の問題(線を直しても
> 変わりません)。黄なら**配線**の問題です。青にならないと開始できません(§7.1)。

> **準備中・準備完了は控えめな明るさです**(眩しさ対策)。故障ではありません。
> プレイ中と終了時(成功・失敗とも)ははっきり光ります。

## 3. プレイヤーへの説明(ブリーフィング)

**最低限だけ**説明する。謎解きの内容は説明しない。

1. **どんな遊びか**
   「無線の向こうの担当者と話しながら、時間内に装置を解除してください。
   失敗すると風船が割れます。」
2. **セーフティーグラスの装着**(必須)
3. **エレクトロニッパーの扱い方**
   - 線だけを挟んで切ること。
   - 他の部品や指を挟まないこと。
4. **難易度を選んでもらう**(イージー / ノーマル / ハード)

| 難易度 | 制限時間 | 課題数 | 対象 |
|---|---|---|---|
| イージー | 5分 | 2 | 初めての人・お子さん連れ |
| ノーマル | 7分 | 3 | 標準 |
| ハード | 10分 | 4 | 経験者・自信のある人。**ヒントで正解を直接教えません** |

> **プレイ中、マネージャーはヒントを出しません。** 進行はすべてナビゲーターが行います。

## 4. ゲーム開始

Coreが**青点灯**であることを確認してから、**対象チームの周波数**でトランシーバーに向かって話す。

### 4.1 開始申告(定型文)

> **「こちらマネージャー。CoreID 3701 難易度ノーマルで開始してください。どうぞ。」**

ナビゲーターが復唱して応答する。

> 「こちらナビゲーター。CoreID 3701 難易度ノーマルで開始します。」

**復唱が正しければ成功**。カウントダウンが始まり、ナビゲーターから第一声が流れる。

### 4.2 申告に必ず含める3要素

このうち**1つでも欠けると開始しません**(プレイヤーの雑談で誤って始まらないための仕組み)。

| 要素 | 言い方 | 補足 |
|---|---|---|
| **CoreID** | 「CoreID 3701」 | 数字4桁。Core本体の銘板に書いてある |
| **難易度** | 「難易度ノーマル」 | 下表の言い方ならどれでもOK |
| **開始の意思** | 「開始してください」 | 「始めてください」でもOK |

**難易度の言い方**(どれでも通ります)

| 難易度 | 通る言い方 |
|---|---|
| イージー | イージー / いーじー / 簡単 / easy |
| ノーマル | ノーマル / のーまる / 普通 / normal |
| ハード | ハード / はーど / 難しい / hard |

### 4.3 復唱が違っていたら

**言い直すだけでOK**。あとから言った内容で上書きされます。

- CoreIDを聞き間違えられた → もう一度、数字をゆっくり区切って言う
- 難易度が違う → もう一度申告し直す

### 4.4 応答がないとき

| ナビゲーターの反応 | 原因 | 対応 |
|---|---|---|
| 何も応答しない | 3要素のどれかが欠けている | §4.2 を確認して言い直す |
| 「準備が完了していません」 | Coreが青点灯でない | 線の復旧を確認(§2.2) |
| 「接続されていません」 | CoreがWi-Fi切断中 | §7.1 へ |
| 「他のチームが使用中です」 | そのCoreが別チームでプレイ中 | CoreIDを確認する |

## 5. プレイ中

### 5.1 マネージャーの役割

- **ヒントを出さない**。プレイヤーとナビゲーターのやり取りに任せる。
- **安全の監視**に集中する。
  - セーフティーグラスが外れていないか
  - ニッパーの扱いが危なくないか
  - 破裂に備えて周囲に人が近づきすぎていないか
- Management Console で進行を見守る(§5.2)。

### 5.2 Management Console の見方

画面は3つに分かれている。**プレイ中に見るのは Management Console だけ**でよい。

| 画面 | URL | 使う場面 |
|---|---|---|
| Management Console | `/manager` | **プレイ中の監視**。これを開いておく |
| 履歴一覧 | `/manager/history` | 終わった回を探す(§6.3) |
| セッション詳細 | 履歴一覧から行をクリック | 1回分をじっくり振り返る(§6.3) |

Management Console の**セッション**の行で今の状況が分かる。

| 列 | 意味 |
|---|---|
| 状態 | `playing` = プレイ中 / `defused` = 成功 / `exploded` = 失敗 |
| 進行 | 「2 / 3」= 3課題中2つ目。下に課題名 |
| 残り | 残り時間 |
| **現在の正解** | **今の課題の答え**。プレイヤーには絶対に見せないこと |
| 無線 | 担当している無線のID |

**交信ログ / 進行記録**では、会話と装置の動きが時刻付きで1本の流れで見える。
どこで詰まっているかを把握するのに使う。

> **「現在の正解」は画面をプレイヤーに見せない前提の情報です。** 画面の向きに注意してください。

### 5.3 混線について

たまにナビゲーター以外の声が無線から聞こえます(**演出です。故障ではありません**)。

- **邪魔者**(「赤を切れ!」など嘘の指示) — ノーマル以上で流れます。正解は言いません。
- **環境ノイズ**(駐車場の誘導など無関係な業務連絡)
- **不穏な通信**(他の現場の失敗など)

プレイヤーが混乱していたら「無線が混線することがあります」とだけ伝えてOKです。

## 6. 終了

### 6.1 解除成功

- Core が**緑点灯**。残り時間がスコアとして表示され続ける。
- 無線から成功の効果音とお祝いのメッセージが流れる。
- **スコア(残り時間)を読み上げて称える**と盛り上がります。

### 6.2 失敗(爆発)

- Core が**赤点灯+ブザー**になり、**約2秒後に風船が破裂**する。
- 破裂音が鳴るので、**周囲に人が近づいていないか確認**する。
- 無線から失敗の効果音とメッセージが流れる。

### 6.3 次のプレイへ

1. **無線でリセットを申告する**(§6.4)
2. 割れた風船を片付け、新しい風船をセットする
3. 切断された線を復旧する
4. Core が青点灯になったら §4 へ

### 6.4 リセット(キルスイッチ)

**秘密ワードを含む定型文**で申告する。プレイヤーが真似してリセットできないようにするための仕組み。

> **「こちらマネージャー。CoreID 3701 リセット でんぱ」**

- 秘密ワードは **「でんぱ」**(サーバー設定 `secret_word`。運営内でのみ共有すること)
- **どの状態からでもリセットできる**(プレイ中・成功後・失敗後)
- 必要な要素: **CoreID + 「リセット」 + 秘密ワード**

**無線が使えないときは、Management Console の「リセット」ボタン**でも同じことができます。

### 6.4.1 強制爆破(打ち切り)

時間内に終わらせたいときなど、**マネージャーの判断でゲームを打ち切る**手段です。

> **「こちらマネージャー。CoreID 3701 強制爆破 でんぱ」**

- **風船が実際に割れます。** 使う前に必ず周囲の安全を確認してください。
- 秘密ワードはリセットと同じ(「でんぱ」)。**キーワードが「強制爆破」**の点だけが違います。
- **プレイ中のみ**使えます。準備中や終了後は反応しません。
- Management Console の**赤い「強制爆破」ボタン**でも同じことができます。

プレイヤーには「時間切れ」と同じに見えます(装置の演出・無線のメッセージとも
通常の失敗と同じ)。**打ち切ったことは伝わりません。**

**そのプレイは失敗として終了します。** 履歴には「爆発」と記録され、
通常の失敗とまったく同じ扱いになります。

> **リセットを忘れずに。** 爆発したあとは Core が赤点灯のままです。
> 次のプレイに進むには、通常の失敗と同じくリセット申告が必要です(§6.3)。

> **使いどころ**: 終了時刻が迫っている / プレイヤーが続行を望まない、など。
> 迷ったらリセット(§6.4)を使ってください。風船が割れません。

### 6.5 終わった回を振り返る

**履歴一覧** (`/manager/history`) に過去のセッションが新しい順に並ぶ。
日付・Core・結果(解除成功 / 爆発)で絞り込める。

**行をクリックすると詳細**が開き、その回の全部が読める。

- 概要 — 開始時刻・難易度・担当ナビゲーター・結果・スコア
- **全課題の正解** — プレイヤーが到達しなかった先の課題も含めて見える
- 交信ログ全文 — 会話と装置の動きが時刻付きで最初から最後まで

「なぜ詰まったか」「ナビゲーターの案内は適切だったか」を後で確かめるのに使う。
**テキストで保存**を押せばファイルに落とせる。

> 詳細には**正解が全部載っています**。プレイヤーの前で開かないこと。

記録は Valkey に保存されるので、**サーバーを再起動しても残る**。

## 7. トラブル対応

### 7.1 Coreが青点灯にならない / 画面に出てこない

**まずフルカラーLEDの色を見てください。原因が分かれます。**

| 色 | 原因 | 対応 |
|---|---|---|
| **紫の点滅** | Wi-Fiに繋がらなかった | アクセスポイントを確認し、Coreの電源を入れ直す |
| **紫の点灯** | Wi-Fiは繋がったがサーバーに繋がらない | サーバーが起動しているか確認(`docker compose ps`)。接続先の設定も確認 |
| **黄の点滅** | 線が切れている | 点灯しているLEDの色の線を復旧する |

紫のままのときに**線を直しても青にはなりません**。先にサーバーとの接続を直してください。

そのほかの確認:

| 確認 | 対応 |
|---|---|
| 画面の「デバイス」に出ているか | 出ていなければ上の紫の行を確認 |
| 状態が `setup` のままか | 線の復旧漏れ。**全色のLEDが点灯する**まで確認 |

Coreの電源を入れ直すと必ず準備中から始まります(途中復帰はしません)。

### 7.2 無線が繋がらない / ナビゲーターが応答しない

| 確認 | 対応 |
|---|---|
| 画面の「無線 (bridge)」に出ているか | 出ていなければ radio-bridge の再起動 |
| 「外部API」にエラーが出ていないか | 出ていれば §7.3 へ |
| 周波数は合っているか | 対象チームの周波数か確認 |

### 7.3 ナビゲーターが黙る・応答が遅い

生成AIの障害の可能性があります(**自動復旧はしません。マネージャーの判断で運用します**)。

1. Management Console の「外部API」でエラー件数と内容を確認する
2. 一時的なものなら数十秒待つと戻ることがある
3. 戻らない場合:
   - プレイヤーに「通信状態が悪い」と伝える
   - **リセットして仕切り直す**(§6.4)、または
   - そのプレイは**マネージャーが口頭で進行を代行**する
     (画面の「現在の正解」を見ながらヒントを出す)

### 7.4 風船が割れない

破裂の失敗は装置側では検知できません。**物理的に対応**してください。

1. プレイヤーを装置から離す
2. マネージャーが安全に風船を処理する
3. リセットして次の準備へ

### 7.5 プレイ中にCoreの電源が落ちた / Wi-Fiが切れた

- **Wi-Fiが切れてもゲームは続きます**(装置単体で動作します)。画面の表示だけが止まります。
- **電源が落ちた場合はゲームが終了**します。リセットして最初からやり直してください。

### 7.6 Coreが突然すべて消灯した(電池切れ)

**バッテリーが減ると、Core は電池を守るため自動で停止します。**
このとき**すべてのランプ・表示が消えます**(故障ではありません)。

- 停止する前に、Management Console の**電池の欄が赤く**なります。
  早めに気付けるよう、プレイの合間に確認してください。
- 停止した後は、画面の**デバイスの行が薄くなり「切断」**と出ます
  (反映まで最長1分ほどかかります)。
- 停止したら**バッテリーを交換し、電源を入れ直して**ください。
  電源の入れ直し以外で復帰しません。
- プレイ中に停止した場合、そのゲームは終了です。リセットして最初からやり直します。

> **消灯している = 電池切れか電源オフ**です。見分けるには電源スイッチを
> 確認してください。電池切れなら交換が必要です。

## 8. 複数台を同時に運用するとき

- Core は台数分**別々のCoreID**を持っています。**申告時は必ずIDを確認**してください。
- チームごとに**トランシーバーの周波数が分かれています**。
  申告は**対象チームの周波数**で行ってください(違う周波数だと別のチームに繋がります)。
- あるチームのCoreが爆発すると、**他のチームの無線に「別現場の失敗」の通信が流れる**ことがあります(演出です)。

- [ ] `docker compose up -d` でサーバー起動
- [ ] Management Console が開ける
- [ ] **無線でカラスが返事をする**(§1.2)
- [ ] Coreが台数分、画面に出ている
- [ ] 無線(bridge)が必要数、画面に出ている
- [ ] 外部APIにエラーが出ていない
- [ ] 風船・予備の配線・ニッパー・セーフティーグラスの数を確認
- [ ] 紙資料(モールス表・シート類)を各Coreの隣に配置
- [ ] 秘密ワードを運営内で共有(プレイヤーに聞かれない場所で)

### 1プレイごと

- [ ] 風船をセット
- [ ] 全配線を復旧 → **青点灯**を確認
- [ ] セーフティーグラスの装着を確認
- [ ] 難易度を聞く
- [ ] 無線で開始申告 → **復唱を確認**
- [ ] (終了後)リセット申告

### 撤収時

- [ ] 全Coreの電源を切る
- [ ] `docker compose down` でサーバー停止
  (**記録はValkeyに保存されるので、後から履歴を見返せます**)

## 10. 困ったときの一言集

| 場面 | 言い方 |
