## 1. 共通事項

### 1.1 色体系

kPush / kLED / kLine の3系統に共通の5色(`game_session_design.md` §3)。
**紙資料の色は実機の配線色と厳密に一致させる**。

| 記号 | 色名 | 用途 |
|---|---|---|
| A | 赤 | 配線・LED・ボタン |
| B | 黄 | 〃 |
| C | 緑 | 〃 |
| D | 青 | 〃 |
| E | 白 | 〃 |

- 記号(A-E)は**サーバー内部の識別子**であり、**紙資料には印刷しない**。
  プレイヤーが見るのは色そのものだけ。
- 色覚多様性への配慮として、色面だけでなく**色名(赤/黄/緑/青/白)も併記**する。
  白は紙面上で見えないため、**枠線付きの白**または「白」の文字で示す。

### 1.2 印刷・運用の要件

- 会場の照明下で読める十分なコントラストを確保する。
- プレイヤーは**セーフティーグラス着用・立ったまま**参照するため、
  文字サイズは大きめ(本文14pt相当以上)にする。
- 装置の隣に置くため、**A4横**を基本とする(複数枚に分けるか1枚にまとめるかは
  制作時に判断)。
- 濡れ・折れに備え、ラミネート加工を推奨する。

## 2. モールス対照表 (203 暗号電文 用)

### 2.1 用途

LEDがモールス信号で表示する語をプレイヤーが解読し、
**その語の頭文字に対応する色の線を切る**ために使う。

ナビゲーターは「解読した単語の頭文字を対照表で引き、その色の線を切ってください」
と指示する。色名は最後まで言わない。

### 2.2 印刷内容(この表をそのまま印刷する)

A-Z の全26文字を印刷する。色は**5色の循環割当**
(A=赤, B=黄, C=緑, D=青, E=白, F=赤, G=黄, …)。

|---|---|---|---|

| B | `－・・・` | BRAVO | 黄 |
| C | `－・－・` | CHARLIE | 緑 |
| D | `－・・` | DELTA | 青 |
| E | `・` | ECHO | 白 |
| F | `・・－・` | FOXTROT | 赤 |
| G | `－－・` | GOLF | 黄 |
| H | `・・・・` | HOTEL | 緑 |
| I | `・・` | INDIA | 青 |
| J | `・－－－` | JULIETT | 白 |
| K | `－・－` | KILO | 赤 |
| L | `・－・・` | LIMA | 黄 |
| M | `－－` | MIKE | 緑 |
| N | `－・` | NOVEMBER | 青 |
| O | `－－－` | OSCAR | 白 |
| P | `・－－・` | PAPA | 赤 |
| Q | `－－・－` | QUEBEC | 黄 |
| R | `・－・` | ROMEO | 緑 |
| S | `・・・` | SIERRA | 青 |

| U | `・・－` | UNIFORM | 赤 |

| W | `・－－` | WHISKEY | 緑 |

### 2.3 レイアウトの要件

- **色は文字ごとに色面(塗り)で示す**。行全体を塗ると見やすい。
- フォネティックコード列は**あってもなくても成立する**が、あると
  プレイヤーが「ゴルフ」と語で報告でき、無線のやり取りが自然になる
  (ナビゲーターは語での報告・1文字ずつの報告のどちらも受け付ける)。
- 短点・長点は**視覚的に長さの差が明確**になるよう描く
  (`・` と `－` の記号、または実際の長短のバー)。
- 26行は多いので、**2列組**(A-M / N-Z)にすると1枚に収まりやすい。

### 2.4 実際に出題される語

実装が出題する候補は以下の15語(各色3語)。**表は全26文字を印刷する**が、
出題されるのはこの範囲であることを制作時の確認に使う。

| 頭文字の色 | 出題される語 |
|---|---|
| 赤 | ALFA, KILO, PAPA |
| 黄 | BRAVO, GOLF, LIMA |
| 緑 | MIKE, HOTEL, ROMEO |
| 青 | DELTA, INDIA, XRAY |
| 白 | ECHO, TANGO, OSCAR |

候補語を増減する場合は
`app/game-server/scenarios/stages/203_angou_denbun.toml` を編集する。
無効化中の `304_angou_denbun_hard.toml.disabled` も同じ候補語を持つため、
**304 を復活させるときは両方を揃える**。
**各色に最低1語は残す**こと(どの色が残っていても出題できる必要がある。
`puzzle_stage_ideas.md` §5)。

### 2.5 表示タイミング(参考)

デバイスは ITU 標準タイミングでモールスを表示する
(`game_session_design.md` §6.1)。単位長は300ms。

| 要素 | 長さ |
|---|---|
| 短点 | 1単位(300ms)点灯 |
| 長点 | 3単位(900ms)点灯 |
| 符号内の要素間 | 1単位 消灯 |
| 文字間 | 3単位 消灯 |
| 語の繰り返し前 | 7単位 消灯 |

プレイヤーには「長い消灯が語の切れ目」と読めるため、対照表に
**「長く消えたら最初から」**の注記を入れると親切。

## 3. 記号・数字シート (202 運命の二択用)

### 3.1 用途

点滅している色に応じて、シート上の**記号を数える**か**数字を合計する**。
集計結果を閾値と比較して切る線を決める。

### 3.2 印刷内容の要件

| 項目 | 要件 |
|---|---|
| 記号 | ⚠ などの記号を散りばめる。**数えられる程度に散らす**(固まらせない) |
| 数字 | 複数の数字を配置する |

**数える負荷は「頑張れば数え切れる」程度に抑える**。
カウントダウンと競合するため、100個などの過大な数は避ける。

### 3.3 サーバー設定との連動(必須)

印刷したシートの**実測値**を `config.toml` に登録する。

```toml
[mission_sheet]
symbol_count = 28   # シート上の記号(⚠等)の数
number_sum   = 47   # シート上の数字の合計
```

- **現在の設定値は記号28個・数字合計47**。この値でシートを作るか、
  シートに合わせて設定を書き換える。
- サーバーは**閾値 = 実測値 + 2、比較方向は「未満」**として出題する
  (`puzzle_stage_ideas.md` §7)。記号28個なら「30未満なら○色」となり、
  正解は常に「未満」側になる。
- 実測値と閾値が2しか離れていないため、**数え間違いが直接失敗につながる**。
  記号は数えやすく配置し、紛らわしい類似記号を混ぜないこと。

### 3.4 刷り直し時のチェックリスト

1. 記号を数え直し、`symbol_count` を更新する
2. 数字を合計し直し、`number_sum` を更新する
3. サーバーを再起動する(設定は起動時に読む)

## 4. 回路図シート (205 ブループリント用)

### 4.1 用途

ナビゲーターが**色を言わず「端子T4の線を切ってください」と端子番号だけ**を
指示する。プレイヤーはこのシートで端子番号→配線色を引く。

### 4.2 印刷内容の要件

- **整備マニュアル風の回路図**として、端子番号(T1〜T5)と配線色の対応を描く。
- 表形式で直接書くより、**回路図の中に端子記号と色を配置**する方が世界観に合う。
- 5端子すべてを記載する(どの色が正解になってもよいように)。

### 4.3 端子と色の対応(現在の設定)

| 端子番号 | 配線色 |
|---|---|
| T1 | 赤 |
| T2 | 黄 |
| T3 | 緑 |
| T4 | 青 |
| T5 | 白 |

対応を変える場合は `config.toml` の `[mission_sheet.terminal_map]` を
同じ内容に更新する。

```toml
[mission_sheet.terminal_map]
T1 = "A"  # 赤
T2 = "B"  # 黄
T3 = "C"  # 緑
T4 = "D"  # 青
T5 = "E"  # 白
```

**5色すべてを登録すること**。登録漏れがあると、その色が正解になった
セッションの組み立てが失敗する。

### 4.4 難度を上げる場合(任意)

ロット別の表を複数載せ、「銘板の CoreID 下1桁が奇数ならロット表A、
偶数ならロット表B」のように自分の装置のIDで正しい表を選ばせる
(`puzzle_stage_ideas.md` §2.2)。確認の往復が無線で発生して盛り上がる。

**採用する場合はサーバー側の対応が必要**(現在の実装は単一の
`terminal_map` のみ対応)。導入前に相談すること。

## 5. CoreID銘板

### 5.1 用途

- **音声申告**: マネージャーが「CoreID 3701 難易度ノーマルで開始してください」
  と無線で申告する際に読む(`operation_flow.md` §3)。
- **205 ブループリント**でロット分岐を採用する場合の判定にも使う。

### 5.2 要件

| 項目 | 要件 |
|---|---|
| 桁数 | **数字4桁**(音声認識で扱いやすくするため。`bridge_connection_design.md` §5) |
| 設置 | Core本体の見やすい位置。**プレイ中に隠れない場所**に貼る |
| 視認性 | マネージャーが離れた位置からでも読める大きさ |

### 5.3 ファームウェアとの一致(必須)

銘板の番号は、その個体のファームウェアに書き込んだ ID と一致させる。

```
idf.py menuconfig → Core System Configuration → Device ID (CoreID)
```

(`sdkconfig` の `CONFIG_CORE_SYSTEM_DEVICE_ID`)

**複数台を運用する場合、IDが重複すると別の個体へ指示が飛ぶ**。
台数分の銘板とファームを組で管理すること。
