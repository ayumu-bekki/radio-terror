# 混線音声 生成リスト

`docs/operation_flow.md` §5.1 の混線演出で再生する音声アセットの生成用テキスト。
**Scene / Sample Context の設定値**と読み上げ本文、出力ファイル名をまとめる。

## 生成ツール

このドキュメントの内容は **`app/crosstalk-gen`** で一括生成できる。
設定は `app/crosstalk-gen/crosstalk.toml` の1ファイルにまとまっている。
接続先は Gemini Enterprise Agent Platform で、認証は ADC
(`docs/gemini_enterprise_setup.md`)。発話ごとに model / voice を指定できる。

```bash
cd app/crosstalk-gen
go run . -list                                    # 対象一覧 (APIを呼ばない)
go run . -dry-run                                 # 組み立てたプロンプトを確認
go run .                                          # 生成 (30ファイル)
go run . -only sasayaki_C -force                  # 1つだけ作り直す
```

出力は Ogg Opus で、`game-server` がそのまま読める名前・配置で書き出される。
詳細は `app/crosstalk-gen/README.md`。

**以降の表は `crosstalk.toml` と同じ内容**を人間が読む形で載せたもの。
設定を変える場合は TOML 側を編集し、本ドキュメントも揃える。
Google AI Studio の画面で手動生成する場合も、同じ値をそのまま使える。

## 出力形式とファイル配置

| 項目 | 値 |
|---|---|
| 形式 | **Ogg Opus** (`.ogg`) |
| 配置 | `app/game-server/assets/crosstalk/{系統}/` |
| 総数 | **30ファイル** (jamming 15 + ambient 13 + uneasy 2)。効果音2つは別枠 |

```
assets/crosstalk/
├── jamming/   … 3パターン × 5色 = 15ファイル
├── ambient/   … 13ファイル
└── uneasy/    … 2ファイル
```

サーバーは `crosstalk.go` の `LoadCrosstalkLibrary()` でこの規約どおりに走査する。
**ファイル名がずれると読み込まれず、無言でスキップされる**(アセット未制作でも
起動できる設計のため、エラーにならない)。配置後は起動ログの
`[crosstalk] loaded assets: jamming=3 ambient=13 uneasy=2` で件数を確認する。

## 色サフィックスの対応

邪魔者系のみ `{name}_{色}.ogg` の形式で、色記号は **A-E**。

| 記号 | 色名 |
|---|---|
| A | 赤 |
| B | 黄 |
| C | 緑 |
| D | 青 |
| E | 白 |

## TTS の設定方法

Google AI Studio の TTS には **Scene** と **Sample Context** の入力欄がある。
**両方に同じ内容を書くと指示が競合して効きが弱くなる**ため、役割を分ける。

| 欄 | 役割 | 運用 |
|---|---|---|
| **Scene** | 全体の状況設定 | **全30パターンで共通**。一度設定したら固定 |
| **Sample Context** | 個々の発話の話者・口調 | **パターンごとに書き換える** |

Scene は固定のまま、Sample Context と本文だけを差し替えていくのが効率的。

### Scene(全パターン共通)

```
業務用トランシーバー(特定小電力無線)の通信を傍受している。
進行中の別の通信があり、偶然混線して漏れ聞こえたもので、聞き手に向けて話しているわけではない。
```

「聞き手に向けて話しているわけではない」が重要。これを入れると
ナレーション調にならず、**業務連絡らしい素っ気ない読み**になる。

正本は `app/crosstalk-gen/crosstalk.toml` の `[defaults] scene`。

### 非言語タグ(本文中の `[...]`)

Sample Context が**話者の設定**(誰が・どんな声で)を担うのに対し、
本文中のタグは**文中のどこで**声を張るか・間を置くかという
発話単位の演出を担う。**役割が違うので併用できる**。

```
[breathless] 今すぐ赤を切らないとまずい![shouting] はやく!
```

Sample Context だけでは「息が上がっている男性」までしか伝わらず、
「はやく!」で声を張り上げる指定はできない。

タグは英語表記で書く。日本語のト書きは読み上げられてしまう事故がある。
生成ツールは**「`[...]` は演技の指示です。声に出して読まず…」という一文を
プロンプトに自動で付ける**ため、タグが読み上げられないようになっている。
AI Studio の画面で手動生成する場合は、この一文を自分で添える。

以下の各表の「本文」は、そのまま貼り付けられる形になっている。

## 3. 不穏系 (uneasy) — 2ファイル

世界観を深める。**色や操作の指示は一切しない**。

### 3-1. 黒幕らしき独り言 (`kuromaku.ogg`)

**Sample Context**

```
誰にも聞かせるつもりのない独り言。無線のPTTを誤って押している。
自分に言い聞かせるような小声。途中で不安が漏れる。
```

**本文**

```
[muttering] ……気づかれてる? [pause] [nervously] いや、まだだ。[reassuring himself] まだ大丈夫……
```

ヒバリ黒幕説(`navigator_design.md` §2.2)と響き合わせるが、
**声はナビゲーターとは別にして**、音で直接確定させない。

### 3-2. 別現場の通信 (`uneasy_bessgenba.ogg`)

**Sample Context**

```
極限状態の男性隊員。作戦が失敗した直後の報告。
声が張り詰めて震えている。背後が騒がしい。
最後の「総員退避」の途中で通信が突然切れる。
```

**本文**

```
[strained, shaky] こちら現場B、解体失敗。[louder, urgent] 繰り返す、解体は失敗した。[shouting] 総員退避——
```

#### 注意: このファイルだけは名前固定

ランダム再生に加えて**イベント駆動再生**に使われる。
他チームの Core が実際に `exploded` した直後、Playing 中の別チームの無線へ流す。
サーバーが `crosstalk.go` の `crosstalkEventFile` 定数で**名前指定で参照する**ため、
`uneasy_bessgenba` から変更してはいけない。

会場に響いた本物の破裂音と通信内容が一致する演出なので、
**末尾が途切れる**ことが特に重要。`[shouting] 総員退避——` で
言い切らずに終わらせている。

## 4. 出力形式

**後処理(ノイズ付与・バンドパス等)は行わない方針**。
生成ツールが Gemini TTS の 24kHz PCM をそのまま Opus エンコードし、
`game-server` が読める Ogg Opus で書き出す。

`opus_bitrate = 16000` が既定値で、無線らしい帯域感になる。
`crosstalk.toml` の `[defaults]` で変更できる。

AI Studio の画面で手動生成した場合は 24kHz WAV が得られるので、
別途変換する。

```bash
ffmpeg -i input.wav -c:a libopus -b:a 16k output.ogg
```

## 5. 効果音 (sfx) — 2ファイル


## 決定記録

| # | 決定 | 理由 |
|---|---|---|
| 1 | Scene と Sample Context を役割分担する(Scene=全体状況で固定、Sample Context=話者ごと) | 両方に同じ内容を書くと指示が競合して効きが弱くなる |
| 2 | Scene に「聞き手に向けて話しているわけではない」を明記 | ナレーション調を防ぎ、業務連絡らしい素っ気ない読みになる |
| 3 | 読み上げ本文に非言語タグ `[...]` を入れる(英語表記) | Sample Context は「誰が・どんな声か」しか指定できず、文中のどこで声を張るか・間を置くかは表現できない。役割が違うので競合しない。**一度タグを外した経緯があるが、演出情報が失われるため戻した** |
| 4 | タグを読み上げさせない一文をプロンプトに自動付与する | 「`[...]` は演技の指示です。声に出して読まず…」を毎回添える。これが無いと TTS がタグを言葉として読み上げることがある |
| 5 | 後処理(ノイズ付与・バンドパス)は行わない | 生成ツールが Opus エンコードまで済ませ、そのまま `game-server` が読める形で出力する。工程を増やさない判断 |
| 6 | 邪魔者系の色部分だけを差し替えた同一文面にする | 5色分を別文面にすると、文面から色が推測できてしまい罠として機能しない。タグの位置も5色で揃える |
| 7 | 環境ボイス系のタグは控えめにする | 業務連絡なので過剰な演技指示は不自然。呼びかけと区切りに1〜2個だけ入れる |
| 8 | 環境ボイス系は話者(年代・性別・口調)を全て変える | 同じ声だと「同じ人が別の役をやっている」と気づかれ、世界の広がりが出ない |
| 9 | `uneasy_bessgenba` の末尾を途切れさせる | 他チームの実爆発と同時に流すイベント駆動再生で、通信が断たれた臨場感を出すため |
| 10 | 混線の声をナビゲーター4キャラ・カラスと重複させない | 特に自称犯人がフクロウ(`Charon`)と同じ声だと「ナビゲーターを信じるな」が成立しない。`go test` で機械的に検出する |
| 11 | カラスに `Achird` を割り当てる | それまで声名が未指定で、既定値 `Despina` にフォールバックしていた。疎通確認用でもナビゲーターと区別がつく必要がある |
